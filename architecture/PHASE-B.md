# Phase B1 — membership fence and browser compatibility (2026-10-04)

Continuation of approved architecture construction. Base: 1734f3c5c0654564884c54a8eb4254efe1659151. This changes only inactive architecture adapters and the existing read-only architecture CI. It does not change public literature, the production reader, userscript, backend routes, media, users, summary content or release times.

The current all-time membership fence validates a byte digest, explicit schema/count, record revisions, monotonic serial and short expiry. It preserves known withdrawals across failures and stale replies. The transport and trusted clock are injected; a content hash is not an authentication mechanism. No public membership endpoint is invented or deployed here. A newer membership may suppress a withdrawn or corrected record in an old immutable catalog. A newly added DOI missing in that catalog reports catalog-update-required, never a false global absence. After every asynchronous get/search/hot load the reader rechecks the fence. Failure returns verification-unavailable without deleting data. Positive authorizations cannot survive an expired checkpoint. Previously withdrawn DOI cannot be silently restored; authorized reinstatement needs its own future protocol. Revocation is bounded by refresh/TTL, not instantaneous across disconnected clients.

queue-membership.mjs keeps legacy queue.articles intact and validates it against the complete current member set. It filters NEW candidate jobs only, preserving prior scheduler order and every TOC/figure/Evidence flag. Dormant or missing jobs do not erase coverage/checkpoints. A legal in-flight receipt may be retained after retirement; obsolete job IDs are rejected. The adapter returns dispatchEnabled:false; it is not yet injected into the distributed controller.

--save-fixtures on the shadow builder saves only public data to a seven-day validation artifact. Declared LIVE_FILES remain byte-verified against the actual delivery manifest. Public paper-title-resolutions.json is separately double-read and hashed, because it is not part of that receipt's file list. This limitation is reported, not hidden as receipt-bound evidence.

Browser acceptance uses a TEMPORARY copy of existing src/main.ts with narrow test hooks; production sources are not edited. Chromium and WebKit render the old verified public inputs, then new-reader records with the same unchanged card renderer and frozen public resolution/translation supplements. It compares DOI, title (EN/ZH), authors, date, journal, badge and article link for every record, checks every Archive DOI, Hot membership, exact-DOI search and revocation of an old cached record. External browser requests are mocked; no live account, feedback, analytics or media writes occur. Network errors, exceptions, traces and failure screenshots are retained. This is not a live UI switch, benchmark or end-to-end test of the newly filtered Tampermonkey queue.

Activation remains separate: publish a current membership endpoint from the authorized release pipeline, bind its transport and trust source, wire the queue adapter before Hot-only consumption, and add existing favorites/status/modal regression tests plus rollback checks. Preserve the fixed-slot writer, summaries, raw evidence privacy and concurrent media-delivery work.
