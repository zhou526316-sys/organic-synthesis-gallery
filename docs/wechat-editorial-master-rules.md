# 化之岛公众号「今日精选／往期精选」长期主规范

> **版本：2026-10-11 · 状态：ACTIVE · 适用：本 ChatGPT 项目全部新旧聊天窗口、微信草稿流水线、编辑/封面/图片审核。**
>
> **这是公众号草稿制作的唯一现行编辑基线（single source of truth）。** 历史草稿的版式仅作视觉参考；旧文件中“原生标题只写论文题目”“所有封面固定气泡”“生成封面就算完成”等做法，均不得覆盖此规范。
>
> **规则优先级**：用户在当前任务中明确确认的具体要求 > 本主规范 > \`PROJECT_RULES.md\` 的通用项目安全与工程约束 > \`docs/wechat-editorial-contract.md\` 中不冲突的细化条款 > \`docs/wechat-draft-editorial-gate.md\` > \`docs/wechat-editorial-production-playbook.md\` > 旧日期个案/示例/单篇计划。**安全要求、草稿验收门禁和禁止群发，不得被低级规则或旧样例放宽。** 对单篇科学内容要灵活，不能把某篇的具体机理、图数、作者、封面构图硬套到新论文。

## 0. 新窗口必做：先承接，再制作

当用户说“继续公众号”“今天的精选／往期精选”“制作草稿”“修改封面／正文／阅读原文”时：

1. **先读** \`PROJECT_RULES.md\`、本文件、\`docs/wechat-editorial-contract.md\`、\`docs/wechat-editorial-production-playbook.md\`、\`docs/wechat-draft-editorial-gate.md\`。
2. **读取实际工作状态**：\`main\` 上对应日期的 \`public/wechat-editions/YYYY-MM-DD.json\`、\`public/wechat-featured/YYYY-MM-DD.json\`、实际往期精选 \`public/wechat-retrospective/<slug>.json\`、\`audit/wechat-working/*review-gate.json\`、\`audit/wechat-publisher/latest.json\` 和相关历史验收记录；不能猜测文件不存在、没有 API Key、没有草稿权限或上轮未完成。
3. **尊重最新选题**：只使用用户亲自确认的今日精选与往期精选 DOI/原文/SI，未确认哪篇就保留空缺；不擅自挑选、替换、补足或合并错日期的选题。对于用户明确提供的 PDF/SI，优先以原稿为证据，逐项核对作者、标题、DOI、期刊和图号。
4. **明确当前任务与已有进度**：分清“文字写好／图片生成／仓库审核通过／微信草稿已写入／微信回读通过／正式群发”六种不同状态；不要把任意前一状态称作后一状态。
5. **禁止窗口隔离造成规则丢失**：其他聊天窗口同样必须读这份文件；项目里新的个别口头总结若与本规范冲突，要查用户最新确认记录并修正规则，不允许以“记忆不全”为理由降低标准或请用户反复重述已确认的约束。

## 1. 栏目、批次、选题与数据

- 一期默认**两篇独立微信图文卡片**：**第 1 篇 = 当天新增文献中的「今日精选」；第 2 篇 = 用户选择的「往期精选」**。两篇各有原生标题、封面、正文、DOI「阅读原文」链接；**禁止将两篇内容合为一篇长文章或交换顺序**。
- 如果只选定其中一篇，可先完成该篇的**独立草稿**，保留待选栏目，不得为凑成两篇自行生成另一篇；后续得到用户选题后再组成同一日期的双篇草稿。
- Gallery 正式新增以**北京时间每日 08:00 唯一正式批次**为准，不能恢复旧的 18:00 新增槽；公众号只引用这个正式已发布批次的精确 DOI、期刊数量和总数。未正式上线的 pending 条目不能虚报为当天已新增。
- **当天更新 / 今日精选 / 往期精选是三个不同内容模块**。当正式新增文献 **>5 篇**时，今日更新只显示总篇数及各期刊篇数，**不逐条堆题目或作者**；**≤5 篇**时可按期刊列出中英标题、作者。二维码／当日列表入口独立保留给读者浏览全部新增。
- 公众号作者署名统一为**「化之岛」**；论文作者姓名必须回查真实来源，中文人名绝不能自行推断。已核准个案：\`10.1038/s44160-026-01128-y\` 的作者为**仇友爱**（不是“邱友爱”）；何智涛相关论文按正确姓名署名。**这些名字不是其他论文的默认作者。**
- 当下正式账号仅授权**创建与更新草稿**。禁止自动或擅自群发、发布；旧已发推文除非用户指定，不逐篇改写，也不可擅自重发。

## 2. 微信原生标题：现行规则，不再回退“只有论文标题”

### 2.1 今日精选固定格式

**\`有机合成文献日报｜MM.DD｜今日精选｜期刊：忠实且自然的中文论文标题\`**

例如（历史已验收的版式语法参考）：

- \`有机合成文献日报｜10.09｜今日精选｜Science：通过氧气活化实现酶催化不对称氢膦酰化\`
- \`有机合成文献日报｜10.10｜今日精选｜Angew.：铁–LMCT/镍–SH₂协同催化游离羧酸直接甲基编辑\`

**必须有**“有机合成文献日报”、对应日期、“今日精选”、期刊与中文题目；**不再默认只保留论文题目**，更不能因某张旧封面的文字而删除日报字段。当前默认今日精选封面**不额外添加“今日精选·JACS”等顶部字样**，腾出面积给最大化的 TOC；完整栏目身份由微信**原生标题**负责。旧“封面已经印了栏目，标题只写论文题目”只作为某次被用户特别指明的历史例外，不得用作新稿的默认规则。

### 2.2 往期精选

原生标题要包含**「往期精选｜期刊」**、经核对的代表作者（用户要求时必须出现）和一个忠实自然的中文主题标题。常用形式：

\`往期精选｜Nature Synthesis｜仇友爱等：醇与醇的电化学脱羟基交叉偶联\`

- 若用户指定题目必须出现某位作者，如“何智涛”，必须写出且全文一致；未核对姓名时不能自行杜撰。
- 题目默认忠于原文贡献，符合中文学术语境；**不加多余副标题，不堆新闻化夸张词**。
- **封面图内文字与微信原生标题分工**：封面文字尽量少，不能为了显示全文标题缩小 TOC 或挡住结构；栏目、日期、作者等字段优先放在原生标题。

## 3. 今日精选封面：原始 TOC 最大化，不再制造无效留白

1. **优先取得期刊真正的官方 TOC / graphical abstract**；确实没有、来源验证不通过时，可使用核实的 Fig. 1 / Scheme 等作为替代主图，且内部正确记录为“正文图替代”，绝不能假称官方 TOC。
2. **现行默认样式**：原文 TOC **尽量放大**，以白色/浅色原稿图面为优先；上部**不再重复印“今日精选·期刊”标题栏**。根据微信真实卡片原生标题的空间，仅在需要时于下方留**适度、尽可能窄的深蓝灰/深色标题承托区**，保证微信叠加的白字可读，**任何标题和图形互不遮挡**。不因机械沿用模板给 TOC 留出过量空白。
3. **信息前景不可变**：分子结构、键线、手性楔线、正负电荷、反应箭头、条件、轨道图、图例、数值、颜色编码都直接来自被验证的原始论文图；**禁止让生图模型自由重画结构**。背景替换仅在严格可分离、不会损害信息前景时允许；否则保留白底原貌。
4. **手机实际裁切验收**：同时审 2.35:1 大卡、方形中心裁切、移动端小尺寸及微信叠字安全区。检查颜色、结构、图题、文字上缘、边界以及 TOC 尚可放大的余量。**原图完整 > 标题完整清楚 > 视觉舒适 > 主图尽量大**；应在此前提下不断优化，但**不要让用户每次自己指出同一类遮挡或过度留白**。
5. 对同一篇已被用户确认的封面，只在用户要求的范围内调整。**不得为了“另做一版更漂亮”随意替换已确认的原图或反复生成不同风格。**
6. 视觉历史参考：10 月 8 日 JACS R9 与 10 月 9 日 Science R2 可用于理解用户认可的**大 TOC + 安全标题区**；其中历史文章的标题字段/旧图上栏目字不能覆盖第 2 节的现行标题要求。

## 4. 往期精选概念封面：有学术主题，但不是固定气泡模板

- 默认制作适配微信第二张卡片的**正方形概念封面**。艺术构图可因论文核心设计而异，如反应网络、轨道作用、电极、光能传递、自由基路径、选择性分化等；**不要每篇都采用七个气泡/圆圈**，更不能添加与化学内容无关的分子背景、火花、装饰物或生造“技术感”。
- **尽量减少文字**，保留少数必要的栏目/论文辨识信息；背景配色可以变化，但色彩必须服务于内容，适合学术阅读。
- **关键化学结构如需出现，必须直接从原文正文或 SI 完整抠取**，可透明去背景、统一缩放、排列或分层，**不得凭模型记忆再画**；保持化学键连接、双键位置、价态、取代基、手性中心与楔线方向逐像素和原文对应。删掉无法核对的结构，不能以“概念图”为由容忍化学错误。
- 如果用户**明确选定某一张成品封面**，草稿中必须使用**相同的源图文件字节**，不可擅自重新生成“类似版本”。若仅指示修改作者姓名，则只修改该处文字并核查化学像素完全未变。
- 历史案例：何智涛 *Science* 七圈封面只是**该篇的单独选择**；仇友爱 *Nature Synthesis* 电化学概念封面是**另一篇的单独选择**。两者都不是后续文章可机械复制的通用模板。

## 5. 正文：以顶级科研视野构建论证，而非“高大上”空话

### 5.1 核心任务与逻辑

读者默认已有研究级有机化学基础，但也可能不熟悉该细分方向。全文围绕这篇论文**一个真正的核心科学问题**展开，通常采用以下**可调整的因果路径**：

**30 秒说清做了什么 → 为什么既有方法不能解决 → 作者提出了怎样的设计 → 条件与对照说明哪个要素关键 → 底物范围与合成应用说明可做什么 → 机理证据能证明到哪一步 → 失效边界与实际代价 → 哪些设计原则可以迁移。**

- “高屋建瓴”应体现**问题抽象能力、跨领域比较、证据辨析和可迁移的方法学判断**，不是浮夸修辞、堆形容词或随意评价“革命性”“突破天花板”。
- 先让读者理解反应是什么，再深入催化价态、能垒、HAT/LMCT/SH₂、同位素/CV/EPR/动力学；不要开头堆教科书式 SET 定义。
- 按论文实际分段，重要证据充分展开，次要背景简短；**不要机械固定 10 节、每节 3 段或每篇固定配图数量**。
- 研究问题引领图片与数据，**不是逐图翻译 caption、逐个产物报菜名**。底物部分选代表例说明化学边界和可拓展价值，同时保留反例、低 ee/dr、低收率和条件切换。

### 5.2 机理证据等级与科研严谨性

科学表述必须区分：

1. **直接观测**：产物结构/分离收率、谱图、CV 峰、原位监测、同位素标记与化学计量对照。
2. **有力支持的解释**：自由基钟、捕获产物、控制组结果对特定路径的约束。
3. **计算或相关性证据**：DFT 能垒、构象、光谱变化、峰位变化；注明计算模型与实验条件的对应限制。
4. **作者提出的工作模型**：完整催化循环、未直接表征中间体、捕获先后或定速步骤。
5. **尚未排除的其他可能性**：竞争通道、过还原、溶剂作为活性源、不同底物改变金属价态等。

**绝不能把“符合模型／支持可能性”直接写成“证实全部机理”。** 具体实验数据必须准确：分离收率与 GC/GC–MS/NMR 收率分开，ee、er、dr、区域选择性与 E/Z 不能混淆；电位标明参比电极，电荷标明 F mol⁻¹ 的含义；不同催化剂、波形、光照、无光/温度条件不能混为一个体系。未由源文支持的比较须删去或明确标注为谨慎推论。

### 5.3 中文语感、术语与反“AI 味”

- 用专业、自然、有节奏的**中文科研叙述**，而不是将英文名词和句法逐词硬译。关键英文术语首见可括注，之后采用准确、常见的中文表达。
- 某个词怎么翻必须看具体反应；“区域选择性”“E/Z 构型选择性”“非对映选择性”“对映选择性”必须分清。不习惯的套话和抽象词（“选择性出口”“机理黑箱被打开”“震撼突破”）必须删除。
- 避免机械高频使用“真正……”“不是 A 而是 B”“最值得注意的是”“更重要的是”“可以说”等模板句；有足够证据才能作结论。
- 叙述由浅入深，让材料自然驱动读者追问；不写“后续 Fig. 4/5 很重要”这种没有信息量的过渡句。
- **完整文字稿需做三遍独立复核**：科学证据与数据复核、中文自然语言与去模板复核、研究思路/可迁移设计原则复核；每一遍发现问题都在源稿修正后重新检查。

## 6. 原图、SI 与图文位置：完整性是硬门槛

1. **先读用户提供的正式正文、SI，若提供审稿意见/回复也要读。** 先建立完整 Fig./Scheme/Table/SI 的“论证任务表”，再选图、写段落、裁图；不凭记忆发明图号或填补实验细节。
2. **主文重要图应尽可能覆盖完整**：设计、优化、底物拓展、实际应用、机制证据；关键 SI（如机理对照、同位素、光谱、谱图、SI Table）应在其确实支持论点时补入。不是把所有 SI 谱图机械堆上，也不是只放一两张形式图。
3. 正文图只从原 PDF/Word SI/可靠期刊源**直接截图/渲染裁切**。如果原文 Figure、Scheme 或 Supplementary Table 跨页面，必须**完整呈现或连续拆成多张图**；任何截断箭头、图题、节点、坐标轴、曲线、表头、数据行、末尾公式、结构取代基的截图都**不合格，禁止进入草稿**。
4. **节选需要有意义**：只在正文确实讨论局部数据时节选，图注写“节选”，且保留能独立解释数据的完整标题/表头/组别/坐标/图例；不能用被截断的半页假冒完整图，也不能用“节选”一词为不完整图片开脱。
5. **默认顺序 = 解释该证据的段落 → 对应原文图 → 图注**；唯一例外是经审核的开篇引导图。每张图必须明确原图编号与证据角色，**按语义位置**插入。发现 Fig. 4B 一类图被硬塞到文章最后时，必须检查整篇图位是否整体偏移，而非只移动被指出的一张。
6. 图片中化学结构、轨道图、计算能量、谱线、表格数据**绝不可生成式重绘**。原图若嵌入的 EMF/SVG 发生光谱曲线丢失，必须换可靠的原文件转码而非继续发布缺损图。裁切图在入库前**实际打开检查像素**，不能只看裁切坐标或“可解码”。
7. 每一张图写入结构化清单：**DOI、原 PDF/SI 文件与实际页码、源 Fig./Table 编号、面板范围、导出 PNG 路径、尺寸、SHA-256、图注、对应文章章节与段落**；经独立确认后锁定源图字节。后续只允许基于审核新版本替换。
8. **已知失误必须永久避免**：
   - 何智涛 *Science* 曾把 **Fig. 4B** 放到结语，尽管正文在“底物范围/DBU 异构化”讨论；今后图片必须语义就近。
   - 仇友爱 *Nature Synthesis* 曾把 **Fig. 5e** 的 Ni(I)/Ni(II)/Ni(III) 循环裁掉底部节点；**完整 Fig. 5e 必须包含 Int-I–Int-V、活化、阴极析氢路径**。
   - 同篇 **SI Table S11 实际跨两页**；必须连续显示完整两页或有明确可理解的完整数据摘录，不能只截第一页上半部。
9. 小屏验收看的是**完整内容能否看清**；宽度不够就按逻辑面板拆图，而不是把 20 个结构挤成一张小图。

## 7. 「阅读原文」：精准 DOI、20 秒蓝色动态锁定、无自动摘要

- **今日精选**：
  \`https://gallery.gczhouwld.com/?edition=YYYY-MM-DD&doi=ENCODED_FEATURED_DOI&summary=0\`
- **往期精选**：
  \`https://gallery.gczhouwld.com/?doi=ENCODED_RETROSPECTIVE_DOI&summary=0\`
- **真正的行为门禁**：点击微信“阅读原文”后在 Gallery 加载/异步渲染/手机分页下都自动**定位并滚动至准确 DOI 的卡片**，卡片整体出现**约 20 秒可见的蓝色动态光效**；\`summary=0\` 明确不自动打开摘要弹窗。低动态模式需保留清晰静态高亮。
- 对旧推文的 \`?edition=YYYY-MM-DD\` 老入口，Gallery 应兼容 \`featured\`/\`featuredDoi\` 两种字段并定位当天原精选，避免历史旧链接失效。
- **当天全部文献二维码/日期索引卡**仍使用 \`?edition=YYYY-MM-DD\`，用途是查看当天所有正式新增，与两篇精选各自的 DOI 精准链接不可混用。
- **新稿 fail-closed**：精选 DOI 不存在、链接被误写为首页/单纯日期列表、两个精选互换、链接没有 \`summary=0\` 或 \`draft/get\` 回读不匹配，都**不能认定微信草稿合格**。链接须由用户选定 DOI 生成，不能靠标题模糊搜索。
- 正常网页分享功能可按其自身单独指定的逻辑工作，不可因修复“阅读原文”而强制把所有普通分享默认改成展开摘要。

## 8. 从源稿到微信草稿：不得跳步

**工作顺序固定，文章结构本身可随论文调整：**

1. 读取现有正式网站 08:00 当日记录、旧微信草稿回执、当前选题、正文 PDF 和 SI；锁定 DOI/作者/期刊。
2. 为每篇写一页 **editorial plan**：核心问题、30 秒结果、方法壁垒、设计思路、证据矩阵、图表映射、边界与失败、可迁移研究价值。
3. 生成 **text-only 完整文字稿**；独立完成科学、语言、设计思想三遍审核。
4. 生成 **images-only 图片清单与审图包**：封面与所有正文原图的可见裁图、源证据、尺寸、SHA、段落位置，并独立逐图检查裁切完整性/手机可读性。不能以“文件存在/解码通过”代替肉眼审图。
5. 文字与图片的 \`*-review-gate.json\` 均记 \`pass\`，记录**确切文件指纹**、两篇 DOI/修订号、图数和顺序。**任意正文/图片/封面/标题/图位变动都使旧审核失效，必须先重审再写入。**
6. 在 \`main\` 的受控版本中一次完成当前修订，**只触发一次终端微信 API 写入**：经现有**固定 IP 微信 relay 和已配置的 API 账户**调用 \`draft/add\` 或 \`draft/update\`。修改已存在的草稿时**优先复用相同 media_id**；不存在或身份不唯一不能擅自创建重复草稿或覆盖其他日期。
7. 写入后必须**\`draft/get\` 回读**：严格对照原生标题、DOI、文章顺序、图片 URL/图号与位置、两张封面、摘要说明及两篇精确 \`content_source_url\`。必要时对比旧/新预览，验证仅授权部分变化。检查正文和小卡布局，不能只看微信 API \`errcode=0\`。
8. **编辑自己先审实际草稿**；发现失真、遮挡、图位错乱、链接失效，继续修至合格。**只有写入成功且回读验收成功**，才能提供**新生成的真实** \`https://relay.gczhouwld.com/wechat-preview/...\` 链接。此链接代表 relay 草稿预览，不得伪称已从微信手机原生界面亲眼验证；原生端的最终裁切以用户实机为准。
9. **永远不自动群发**。仅用户明确批准最终发布、且账号具备权限时，才另行走专门发布流程。写草稿权限 ≠ 群发权限。
10. 草稿审校**不依赖 TinyFish**；现有固定 IP relay、微信 API、\`draft/get\` 与审核素材已经构成完成该任务的正式通道。**不能未经核对就回复“我没有 API Key/没有写稿权限，只能给你提示词”。** 也不得暴露 API Key、AppSecret 或其他密钥。
11. **长任务分段、状态可追溯**：有超时风险时分批导图、哈希校验、分步提交，避免整任务因网络中断回到起点；所有确认修改同步 \`main\` 和审阅/回执文件，不能覆盖同轮正常执行的编辑。
12. **不修改无关系统**：公众号草稿任务不擅自改变 Gallery 每日 08:00 正式文献发布、Tampermonkey 抓取、私人 PDF、用户账户系统及其他聊天正在执行的任务。

## 9. 图文验收必须逐项通过

- **身份**：用户实际选的两篇 DOI、论文题目、中文作者姓名、期刊、日期、顺序准确。
- **标题**：今日精选包含“有机合成文献日报｜日期｜今日精选｜期刊：中文题目”；往期精选按已核准作者+主题。没有无授权副标题。
- **封面**：今日 TOC 尽可能大、化学原图不受损、不额外压顶栏、微信白字可读；往期方形主题正确、若含结构均源图抠取、没有无关的气泡套路。
- **正文**：科研视野、逻辑递进、中文自然，数据与引用准确；作者模型与证据分级，限制和失败真实；不堆空泛观点。
- **所有图**：完整结构/箭头/表头/曲线/图例/公式；关键正文及有价值 SI 到位；每图解释、图号、位置、实际图片一一对应，无 Fig4B 式错位或 Fig5e/TableS11 式缺损。
- **微信 API**：同一期单一 media_id、\`draft/get\` 成功、两篇顺序与标题、封面、正文、图片顺序、两篇精确 DOI \`content_source_url\` 一致。
- **网站访问**：点击“阅读原文”能定位目标 DOI，完整卡片显示约 20 秒蓝色光效，不自动弹摘要；日期二维码仍可浏览当天完整收录。
- **交付**：给用户**真实微信回读预览**与已确认状态；严禁以本地 PNG/HTML/ZIP、Git PR、CI 通过或“我正准备”冒充草稿已更新。
- **发送状态**：\`publish_id=null\` / 未群发，用户不额外明确下达群发指令就不得操作。
