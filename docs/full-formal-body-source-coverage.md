# 全部正式 DOI 的科学正文来源覆盖（2026-10-14）

**用户要求**：整个 Gallery 正式文献目录中的每篇论文都应纳入正文检索补充工作，不能只选 826 篇历史日期确认 DOI，也不能每次人工只推进 20 篇。

## 一次发起，自动覆盖整个正式书目

- 唯一输入来自最新正式 `release-delivery.json`，以及同一 `architectureCatalogId` 对应的 `/api/literature/catalog-view` 全量分页。**不传 `dateTo` 过滤**；严格核对每一个正式 DOI 和 revision，拒绝候选 staging、跨代次或丢 DOI 的计划。
- 范围包括创刊前历史归档、2026年7—9月、2026年10月以后、正式目录中发表日期尚未核实者；源扫描分类保留这四组，未知日期不自动算作“已完成正文”。
- `.github/workflows/full-formal-body-source-coverage.yml` 只要被触发一次，就根据实际正式 DOI 数自动生成全部分片任务，**没有 20 篇的业务上限，也无需人工逐窗继续**。
- 默认每 100 篇为一个纯技术分片，三个分片最多同时运行，以防止单次连接超时、来源速率限制和平台配额冲击；无论正式目录增长至多少篇，所有分片均由同一次工作流动态生成。
- 复核端将分片全部重新核对，检查重复、缺少、顺序、来源 hash、来源失败、目录变动。只在全量正式 DOI 均获得非暂时性来源结论时声明 `sourceAuditComplete=true`；429、HTTP失败及网络错误分别记录待重试，不把它们计作正文已抓齐。
- 每个分片即使中途受阻，也尽可能留有只读结构化证据；官方 Actions artifact 暂存30天。在实际结果出炉后，采用新的 Git 审计检查点固定准确来源状态与可恢复信息，不把旧 826 分母报告当作全库结果。

## 来源扫描与正文入库是不同工作

1. **来源覆盖**：对全部正式 DOI 查询官方 Europe PMC；取得 DOI 对应的 OA JATS 时，只提取文章级许可证类别、科学章节／段落／图表计数和 XML SHA，不在 Git、D1、R2 保存 XML/论文全文或私人 PDF。
2. **候选复审**：对开放正文候选逐篇核实出版社许可、第三方图表权利、章节与机理/数据含义、正文完整性及 DOI revision。JATS `complete_candidate` 不是实际全文完整证明。
3. **补充来源**：Europe PMC 不匹配、缺 OA、条款有限制的文章不能直接宣告无正文；需逐篇尝试其他合法来源或拥有阅读权利的用户本机独立检索，严格保留来源失败分类。
4. **正式检索**：公开 `LITERATURE_INDEX_DB` 只接纳单篇核实可公开再利用的来源，经过独立审核后调用受控管理员章节入库接口。没有再利用许可的订阅全文不得被上传至公共 FTS；私人本机检索能力不等于公共全文上传许可。

本工作流不修改当前正式 DOI、08:00 唯一发布时刻、历史23:00 staging、TOC、正文图片、SI、PDF、用户浏览器采集器或已存在的本机结果。每篇论文始终都在**来源与检索覆盖审计**的目标中，但不能把“一律争取正文”宣传成“一律已有合法完整公共原文”。
