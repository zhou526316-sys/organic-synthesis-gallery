# WeChat Editorial Production Playbook

Updated: 2026-10-07  
Status: active  
Scope: Organic Synthesis Gallery 的“今日精选 / 往期精选 / 深度解读”公众号内容

本文是 `docs/wechat-editorial-contract.md` 的操作层手册。合同规定“必须做到什么”，本文规定“以后默认怎么做，才能更快、更稳地做到”。

## 1. 默认读者与深度

默认读者是已经具备有机化学、光氧化还原、自由基、过渡金属催化等基础知识的科研读者，而不是化学入门读者。

因此：

- 不为常规概念单独写教材式背景，例如普通氧化淬灭/还原淬灭循环、常见 SET 定义、常规 HAT/LMCT 基础流程。
- 背景内容只有在它直接解决“这篇论文为什么需要这样设计 / 为什么某个证据能区分两种机制 / 为什么作者的说法容易被误解”时才进入正文。
- 任何背景段落在写入前必须通过三问：
  1. 没有这一段，读者是否会误解本文核心逻辑？
  2. 这一段是否与本文的具体体系、证据或争议直接相关？
  3. 它是否改变后文某个数据/机理的理解，而不仅是补充常识？
- 三问中若有两项为“否”，默认删除。
- 外部文献背景只能解释论文中特定概念差异，不能把精选推文变成教科书章节。

## 2. 写稿前先做“单页编辑计划”

每篇文章在正式写正文前，先形成一个内部 editorial plan；不需要先给用户看，但必须存在并通过自审。

最小字段：

```yaml
paper:
  doi:
  journal:
  title:

core_question: "全文真正要回答的一个问题"

opening:
  result_30s: "30 秒内说明做成了什么"
  bottleneck: "真正卡在哪里"
  study_value: "为什么值得继续读"

design_logic:
  intervention: "作者改变了什么"
  causal_reason: "为什么这可能有效"
  expected_consequence: "如果逻辑成立，应观察到什么"

background_gate:
  needed: true|false
  exact_question_resolved:
  reason_not_textbook:

evidence_matrix:
  - claim:
    level: observed|supports|compatible|computation|author_model|unresolved
    source: "Main Fig./Table/SI/Peer review"
    exact_ref:
    wording_limit:

figure_map:
  - source_ref:
    role: "这张图只回答一个问题"
    placement:
    crop:
    reused: false

scope:
  demonstrated_space:
  failures_and_limits:
  overclaim_to_avoid:

ending:
  synthetic_capability:
  transferable_lesson:
  remaining_uncertainty:
```

没有完成这个计划，不进入正文生成。

## 3. 全文只围绕一条科学主线

推荐顺序不是固定章节模板，而是固定的因果顺序：

`30 秒看懂反应 → 为什么难 → 作者改了什么 → 为什么应该有效 → 条件/结构变化造成了什么结果 → 决定性证据 → 证据只能证明到哪一步 → 替代解释 → 失败边界 → 合成意义`

要求：

- 每一节都回答一个明确问题。
- 每段至少完成“提出问题 / 给证据 / 限定结论”中的一个功能。
- 删除没有信息增量的过渡句。
- 禁止使用“后续 Fig. 4/Fig. 5 很重要”“这里非常巧妙”“值得注意的是……”后面却没有说明具体因果关系的句子。
- “逻辑顺”不等于“证据足”。叙事结构必须服从原文证据。

## 3.1 三层读者收益与“高屋建瓴”标准

精选文章不能只做到“专业且流畅”。默认同时服务三层读者：

1. **跨领域读者**：即使不做该具体方向，也能在不补课一整章教材的前提下理解“问题为什么难、作者改变了什么、证据说明了什么”。术语只在首次影响理解时解释，并优先给操作性定义。
2. **有机化学研究者**：能够看到具体的结构—反应性关系、条件、对照、动力学、光谱/计算证据、scope 与失败边界，而不是只读到结论。
3. **方法学与催化设计者**：每篇至少提炼 1–3 条可迁移的设计判断，例如状态依赖的催化剂优化、多中心电子通信、如何定义真正有区分度的 benchmark、失败底物暴露了哪个反应窗口。

“高屋建瓴”必须从本文证据向上抽象，不能靠大词制造深度。推荐思考阶梯：

`具体现象 → 物理/化学约束 → 作者的设计选择 → 证据如何约束解释 → 可迁移的设计原则 → 仍然不能外推的边界`

要求：
- 每个高阶判断都必须能回指到本文的至少一个具体结构、实验、数据或失败边界。
- 可以跨越到一般催化思想，但不能把一个体系的观察泛化成普遍定律。
- 不用“真正值得看”“最漂亮”“最聪明”“本质上就是”“不是A而是B”等高频判断句来代替分析；这些结构若反复出现会产生明显的模型化写作痕迹。
- 少用整齐划一的三段式、排比式总结。句长、节奏和过渡应随科学内容变化，像研究者在带读论文，而不是模板在逐项填空。
- 对跨领域读者使用类比时，只解释关系，不改写化学事实；类比一旦可能造成机理误导，立即舍弃。
- 章节结尾优先给“这组证据改变了我们对什么问题的判断”，而不是机械复述上一段。
- 最终文字要经过至少三遍独立编辑：**科学证据遍 → 人类语言/去AI味遍 → 跨领域收益与可迁移见解遍**。任一遍修改了关键论断，都要重新做证据核对。

## 4. 开头三块必须形成因果链

默认的三个 opening quick points：

1. **先看做了什么**：只讲反应/能力，不先讲复杂机理。
2. **真正需要解决的瓶颈**：说明为什么已有方法或常规状态难以做到。
3. **为什么值得深入看**：指出这篇工作真正值得研究的科学问题，而不是期刊、产率或“新颖”本身。

三块必须能连成：
`结果 → 障碍 → 科学价值`

不能写成三条互相独立的卖点。

## 5. 图片规则：主文优先、逐图有任务、图文固定关系

### 5.1 主文图优先

- 只要原文主文图对论证有实质作用，原则上应在对应叙事位置展示。
- “尽量展示正文图”不是机械堆图，而是不要因为篇幅方便把关键主文图省掉。
- SI 图用于补充机制、控制实验、失败边界、时间进程、审稿补实验等正文图未能充分展示的内容。
- 不能用 SI 图替代本应出现的主文图。

### 5.2 一张图只承担一个主要论证任务

每张图在 figure map 中必须写清楚：
- 它回答什么问题；
- 哪一段解释它；
- 读者应该看哪里；
- 它支持的是直接观察、相关性、控制、机理模型还是计算。

同一张图默认不重复插入。后文再次引用时写“前文原文 Fig. X”，而不是再次放图。

### 5.3 图文顺序统一

默认规则：

- **唯一例外：开篇核心反应/设计图可以先图后文。**
- 其余正文统一为：**解释文字 → 对应图片 → 图注**。
- 每个描述图片的段落必须明确写 `原文 Fig. X`、`Table X` 或 `SI Fig. X`。
- 不允许同一篇里一会儿“图在文字上面”、一会儿“图在文字下面”，除非明确登记为 lead-image exception。
- 图注必须说明来源和这张图在此处的作用，不只复述“这是 Fig. X”。

### 5.4 多面板图

- 图太密时，按论证拆成多个高分辨率裁图。
- 拆图不能切掉结构、轴、箭头、条件、产物、图例、panel label。
- 如果一幅主图的上下半部分分别承担不同论证，应分开使用并分别解释。
- 原始主文图中的重要板块不能因为裁切而静默消失。

## 6. 证据措辞分级

内部必须给关键机理/因果句标记证据等级：

- **observed**：直接观测/测量到。
- **supports**：控制实验或数据明显支持。
- **compatible**：与某模型相容，但不能排除其他解释。
- **computation**：计算支持。
- **author_model**：作者提出的工作模型/可能机制。
- **unresolved**：现有数据没有解决。

写作词汇对应：

- observed → “观察到 / 测得 / 检测到”
- supports → “支持 / 表明……具有重要作用”
- compatible → “与……相容 / 可由……解释”
- computation → “计算支持 / 计算提示”
- author_model → “作者提出 / 作者据此认为”
- unresolved → “尚不能排除 / 仍无法确定”

除非有直接证据，不把“支持”升级成“证明”。

## 7. 审稿材料的用法

只有真实取得 Peer Review File / rebuttal 时才写“审稿人提出”。

使用方式：

`审稿人质疑了什么 → 作者补了什么 → 新证据解决了多少 → 仍留下什么不确定性`

禁止：
- 把自己的编辑疑问写成“审稿人质疑”；
- 把同行评议当作权威背书；
- 把论文最终接受等同于所有机理问题已被证明。

## 8. 底物范围不是报菜名

底物拓展至少回答：

- 哪些结构类型真正扩展了方法空间；
- 哪些底物需要换催化剂/碱/光源/条件；
- 哪些边界失败；
- 哪些“漂亮例子”只能说明兼容性，不能外推成普适性；
- 收率、dr、ee、NMR yield、isolated yield 是否混用了不同语境。

正文大图有多个 scope 区块时，应逐块解释，不用一句“底物范围广”带过。

## 9. 背景扩展图的使用门槛

自制概念图或外部背景图只在以下情况下使用：

- 能澄清本文中两个容易混淆但后文关键的概念；
- 能直接解释一个决定性实验为何具有区分力；
- 能帮助读者理解本文作者使用的非常规物种/循环/能量关系。

必须：

- 明确标成“自制拓展图”；
- 与原文实验图使用独立编号；
- 指明背景来源；
- 不画成本文的实测机制；
- 不使用生成模型虚构化学结构或数据。

默认不制作“常规知识示意图”。

## 10. 封面与卡片

每日精选：
- 优先使用论文真实 TOC / graphical abstract。
- **化学与数据信息前景不可改动。** 化学结构、键、箭头、条件、标签、轨道色块、图例、坐标、数据等都不得重绘、改色、擦除或生成式替换。
- 若真实 TOC 存在大面积白色/近白背景，可在能明确区分“背景”和“信息前景”的前提下，只扣除背景并换成协调的低饱和深色，让 TOC 主体可以显示得更大，同时避免白色标题与白底冲突。
- 深色背景必须符合正常阅读习惯：稳、柔、低刺激、低饱和、耐看。优先深蓝灰、深灰蓝、深靛灰、炭灰等；避免纯黑、高饱和蓝紫、刺眼渐变或过强黑白反差。具体色相应服从原图主色，而不是固定套一种模板。
- **彩色图案和黑色化学线条不能被深色背景吞噬或干扰。** 如果自动/手动扣背景会伤到轨道、色块、结构、文字或箭头，就不要继续扣；改用原白底的浅色面板承托前景，或保留原图。
- 标题条是备选，不是默认必须。需要时只包住实际白色标题并留少量安全边距，不能为“保险”做成厚重色块。
- 如果以上处理仍然会牺牲化学信息或阅读舒适度，**允许并优先选择把原图适当缩小**。宁可图稍小，也不能破坏原图、挡住标题或制造视觉不适。
- 不能为了“图尽量大”而降低原图完整性、标题可读性或阅读舒适度。执行优先级为：**原图信息完整性 > 标题可读性 > 阅读舒适度 > 图尽量大**。

往期精选：
- 小卡使用单独优化的方形封面。
- 可使用低饱和深色外场和一个保留原始化学图的浅色事实面板；这适合需要在小卡中兼顾舒适深色视觉与黑色化学结构可读性的情况。
- 可使用抽象艺术意象，但不能虚构化学结构。
- 小卡首先保证主题识别和中心构图，不堆作者履历、奖项、口号。
- 若使用原文结构/轨道图作为事实锚点，只能裁切和排版，不改变其中化学元素。

封面与正文图片是两个不同任务，不能拿正文拼图直接缩成卡片封面。

## 11. 高效率生产顺序

以后默认按以下顺序执行，避免反复写入公众号：

1. 锁定用户选择的 DOI；不自动替换精选。
2. 读取主文、SI、peer review（如有）和已有深读记录。
3. 生成单页 editorial plan。
4. 一次性完成 evidence matrix。
5. 一次性完成 figure map，优先覆盖主文图。
6. 做所有裁图并冻结为版本化 raster。
7. 生成完整 text-only 稿。
8. 生成 images-only 稿。
9. 独立审核文字与图片。
10. 只在两者通过后合成正文。
11. **一轮编辑 revision 只触发一次公众号 draft/update。**
12. `draft/get` 回读。
13. 检查实际两篇文章顺序、封面、390/690px 正文、图号、图片顺序和缺图。
14. 只有用户明确要求发布时才进入最终发送。

微调不要每改一句就触发一次微信写入；先在源稿中批量完成，再一次更新草稿。

## 12. 默认禁止项

后续无需用户重复指出，默认禁止：

- 教材式基础背景占用精选正文；
- “后续 Fig. X 很重要”这类无信息句；
- 未指出图号却讨论某张图；
- 同一篇中图文顺序无规律切换；
- 省略关键主文图，却放大量次要 SI 图；
- 一整张密集多面板图缩到手机上不可读；
- 一张图重复承担多个完全不同的论证；
- AI 重绘化学结构、谱图、数据；
- 把模型或相关性写成“证明”；
- 用“高收率/高影响因子/很新颖”代替科学价值；
- 用户未选择时自动替换“今日精选/往期精选”；
- 文字、图片还在改时反复写入微信草稿。

## 13. 发布前 90 秒检查

每篇至少快速回答：

- 一句话能说清核心问题吗？
- 开头三块是“结果→瓶颈→价值”吗？
- 有没有一段只是教科书背景？有则删。
- 每个关键因果句能找到证据来源吗？
- 所有主文关键图是否都有对应解释？
- 每段涉及图时是否写了准确 Fig./Table/SI 编号？
- 除 lead image 外是否统一“文字→图→图注”？
- scope 是否既写成功也写失败？
- 有没有把作者模型写成事实？
- 有没有无意义的“重要/巧妙/值得注意”？
- 手机端图片是否能读？
- 是否只在这一 revision 最后触发一次 draft/update？

## 14. 与其他规则的关系

优先级：

1. `PROJECT_RULES.md`
2. `docs/wechat-editorial-contract.md`
3. `docs/wechat-draft-editorial-gate.md`
4. 本 playbook
5. 单篇 editorial plan

单篇计划可以根据论文调整章节，但不能降低上述证据、图片和审阅标准。
