# WeChat Editorial / Publishing Postmortem — 2026-10-05

Status: accepted lessons for future automation
Scope: 2026-10-05 daily feature + retrospective bundle

## What worked

- The publisher can create/update a real two-article WeChat draft bundle and verify it with `draft/get`.
- The daily release can be compressed to journal counts when the literature count is large, while still showing several real Gallery mini-cards as visual navigation.
- Main text, SI and peer-review files can be used as separate evidence layers for deep editorial reconstruction.
- PDF-native figures can be rendered at high resolution and inserted at the exact argumentative point.
- Daily feature and retrospective can coexist in one outgoing bundle while remaining separate WeChat articles/cards.

## Editorial lessons

### 1. Deep reading must precede writing

Do not start from a fixed article template and then fill it with facts.

For every selected paper, first identify:

- what is fundamentally difficult;
- why it is difficult at the mechanistic / physical-organic / reagent-design level;
- what exact bottleneck the authors changed;
- why the design should alter that bottleneck;
- which experiments support each causal link;
- which alternative explanations remain;
- what the failure cases reveal;
- what new synthetic capability is actually purchased.

The writing path should then move from intuitive to deep:

`30-second reaction picture → why the problem is hard → design logic → condition logic → decisive evidence → deeper mechanism/speciation/energetics → alternatives/reviewer challenge → failures → synthetic meaning`.

### 2. No invented narrative logic

Never create a story such as “the clever part is splitting two things apart” unless the paper itself supplies a causal chemical reason.

Editorial logic must come from:

- the main paper;
- SI;
- peer review / rebuttal if supplied;
- direct comparison with prior art.

A coherent story is not evidence.

### 3. Chinese-first language

The body should use normal Chinese chemistry language wherever possible.

Use Chinese directly for common terms such as:

- 光氧化还原;
- 伯胺 / 仲胺;
- 亲核试剂 / 亲电试剂;
- 自由基;
- 钛醇盐;
- 碳正离子;
- 过渡态;
- 底物范围;
- 收率;
- 机理;
- 中间体.

Keep abbreviations such as RLT, LMCT, HAT, DFT, IRC, HTE, het-SH2 only when useful for literature recognition. Define them in Chinese at first appearance and then prefer Chinese wording.

Avoid mechanical half-Chinese / half-English substitutions.

### 4. Each figure must have one job

Every image must answer one specific question.

- No duplicate use of one figure for different arguments.
- No decorative spectrum or scheme.
- No unrelated panels.
- No half-cut neighbouring paragraph / caption / page header.
- Use final-PDF crops where possible.
- Render high-resolution first; crop second.
- A figure explanation belongs directly below that figure.

If a paper figure is too dense, split it into argument-specific panels instead of shrinking the entire figure.

### 5. Cover QA must use the actual WeChat display mode

A cover can look good full-screen and still fail as a WeChat card.

For the second article:

- inspect the actual small-card thumbnail;
- inspect the centered crop WeChat applies;
- keep face/title/core identity inside the safe region;
- do not shrink a wide scientific poster into a tiny square;
- do not use placeholder-like portrait + empty color block layouts;
- do not add awards, slogans, quotes or credentials unless explicitly requested.

### 6. Article titles and cover titles are different surfaces

Daily main-article title pattern:

`有机合成文献日报｜日期｜今日精选｜期刊：中文论文标题`

Retrospective title pattern:

`往期精选｜作者：中文论文标题`

The Chinese paper title should faithfully translate the original title, not become a marketing headline.

### 7. Daily update block should stay compact

If daily release count is greater than 5:

- body text shows only total count + per-journal counts;
- do not enumerate all titles;
- the Gallery jump card may show several real miniatures;
- editorial space belongs to the selected deep-read article.

## Production / automation lessons

### 1. Draft/get is the only preview source of truth

Do not trust a locally generated preview.

Required sequence:

1. build article;
2. update real WeChat draft;
3. call `draft/get`;
4. render preview from returned WeChat content;
5. inspect both article bodies and both card thumbnails.

### 2. One trigger per editorial revision

Multiple overlapping publisher runs caused queueing and a receipt rebase conflict.

Future rule:

- do not fire a new publisher trigger while an earlier WeChat publisher run is queued or in progress unless the earlier run is explicitly obsolete and cancelled;
- maintain one authoritative requested revision id;
- receipt writes must be single-writer or conflict-safe.

### 3. Separate editorial QA from transport success

A successful API response means only that the draft was stored.

A draft is not “ready” until automated QA confirms:

- title format;
- article count;
- selected DOI;
- no duplicate figures;
- no obvious mixed-language residue;
- no cropped figure fragments;
- correct second-card cover;
- Gallery compact block rules;
- required originality / AI-assistance disclosure.

### 4. Image QA needs machine-checkable rules

Before draft update, the pipeline should reject:

- figure reused twice;
- cover with excessive blank area;
- second-card crop where core subject/title falls outside safe region;
- body figure whose crop includes excessive page margin/header/footer;
- generated chemistry structures;
- tiny unreadable figures.

### 5. Editorial generation should be staged

Recommended production stages:

1. **Source pack**  
   main text + SI + peer review + prior-art comparison + selected original figures.

2. **Deep-reading model pass**  
   extract bottleneck, causal design logic, evidence hierarchy, alternatives, failures, practical limits.

3. **Editorial plan**  
   create paper-specific shallow-to-deep outline before prose generation.

4. **Writing pass**  
   Chinese-first body, figure placements and captions.

5. **Scientific audit pass**  
   check each mechanistic statement against source evidence and downgrade overclaims.

6. **Reader audit pass**  
   check whether a non-specialist organic chemist can follow the progression.

7. **Visual QA pass**  
   crop, resolution, duplication, caption, cover safe-area tests.

8. **WeChat draft update + draft/get**.

9. **Rendered-card QA**  
   check actual first-card and second-card appearance, not only body HTML.

10. **Publish / send only after all gates pass**.

## Automation graduation criteria

The user should no longer need to assist with sending only after the pipeline can pass all of the following without manual correction for several consecutive issues:

- selects or consumes the user-approved daily / retrospective choices correctly;
- deep-reads main text + SI + peer review when available;
- produces paper-specific, evidence-led logic rather than a fixed story template;
- uses Chinese-first terminology;
- selects non-duplicated original figures and crops them correctly;
- creates a readable first-card title and second-card cover;
- generates a real WeChat draft and validates with `draft/get`;
- automatically rejects malformed titles, image duplication, jargon residue and bad crops;
- never sends before all QA gates pass;
- records an immutable release receipt and prevents duplicate sends.

## Remaining hard blocker for zero-touch sending

Current personal-subject Official Account workflow supports automated draft creation/update and preview, but final sending/publication still depends on the account's available WeChat permissions.

Zero-touch delivery requires one of:

- an Official Account with the required official publish / mass-send API permissions and quotas; or
- another explicitly approved production control path that can legally and reliably perform the final UI action.

Until that final permission/control path is verified, the correct automation target is:

`fully automatic source → editorial → QA → WeChat draft`

with only the final send action remaining manual.
