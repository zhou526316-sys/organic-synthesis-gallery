## Implemented behavior

Bridge version 2.2.23; capture protocol remains 6.2.20. Tokens/checkpoint storage keys and DOI/task/tab/serial-controller guards remain compatible.
Client postAcquiredImage applies to TOC and body image uploads. At most three total image POST attempts; retains the SAME acquired bytes in memory during this task and does not redownload the publisher asset within the retry. Honors numeric/date Retry-After, task ownership and deadline. Defers excessive delays rather than violating Retry-After. Stops on explicit extension denial, authentication/identity errors and nonretryable integrity failures. This is NOT a persistent binary outbox across task-tab closure or a guarantee that an exhausted old failed image can be recovered without reacquisition.
Upload diagnostics retain sanitized actual HTTP status, request transport, response content type/format/size, exposed CF-Ray, actual Worker request/code, storage operation, objectStored, retryability and Retry-After. Raw response HTML, auth, token and image bytes are not logged. A 503 without Worker code remains response_without_worker_error_code; no invented diagnosis.
Worker stage-storage revision 2026-09-23.1. Existing valid content-addressed bytes are reused only after digest verification. New bytes are checksum-confirmed; old objects are not deleted during restaging. Corrupt index fails closed rather than being replaced with an empty library. Shared index updates compare ETag and re-read/merge after conflicts. Explicit transient R2 failures receive bounded backoff; returned errors distinguish object write/index read/index write and disclose objectStored versus indexCommitted without claiming stored=true until receipt is valid.
This does not refactor every unrelated legacy writer and does not enable automatic promotion. Current official Cloudflare R2 worker API and error-code documentation was checked for conditional-write/checksum behavior; platform limits were not asserted to be the proven historical failure cause.
