## What the installed release does

Captures specific failure evidence automatically: task DOI, actual article/source identities when observable, controller/capture version, job identity, image label, failing stage/request path, HTTP status, exposed content type, measured dimensions/byte count, request elapsed time and Retry-After when exposed, retry count and sanitized errors.
Intermediate candidate failures are checkpoints with status=progress, not fabricated final failed-paper results. Final success/partial/failure preserves prior failure context. HTTP 0 without an explicit runtime error stays an unverified transport cause, not an assertion of CORS, proxy, publisher or credential failure.
The former report-loss race is fixed: finishPairedJob enqueues sanitized evidence in local persistent storage BEFORE making resultKey visible; the long-lived Gallery page sends it after the publisher tab closes. A separate diagnostic lease and one sender avoid interacting with the capture controller's task lock.
The sender checks every 10 seconds, requires matching DOI and positive stored/attemptId receipt, and retains pending reports with 30-to-300-second backoff on failure. Checkpoints are coalesced and the queue is bounded to 200 records, with an explicit overflow state. Ten seconds is the check cadence, not guaranteed end-to-end delivery. Browser throttling, network, authorization and queue backlog can increase latency.
The nonmodal panel displays current DOI/image stage/quality, stored vs discovered counts, checkpoint reuse, completed-paper totals, stale progress age, and diagnostic delivery status. It polls local Tampermonkey state once per second; background timing is not guaranteed. It distinguishes staged media from published cards.
