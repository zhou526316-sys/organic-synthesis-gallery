# Bridge 2.2.28 — per-DOI failure skip / continuous capture

Recorded 2026-09-24 15:18 Asia/Shanghai.

## User requirement

A failure in one paper must not pause the entire Tampermonkey capture mainline. Former controller stop conditions that are local to one DOI should become skip-and-continue behavior.

## Behavior shipped

Bridge 2.2.28 keeps capture protocol 6.2.20 and changes controller disposition only.

Per-DOI skip/continue reasons:
- bound_publisher_heartbeat_missing
- task_tab_handle_unavailable
- previous_task_tab_not_closed
- controller_timeout

For these reasons the controller:
1. invalidates/cleans the owned active job;
2. records the controller diagnostic;
3. persists the failed result/attempt when applicable so existing retry cooldown applies;
4. increments skipped/lifecycle counters;
5. continues to the next DOI instead of writing CONTROLLER_STOP_REASON.

Hard-stop reasons intentionally retained:
- controller_lease_lost
- another_task_still_active
- capture_server_upgrade_pending
- explicit user pause/abort

This separation preserves ownership/protocol safety while preventing one publisher/article failure from pausing the queue.

Bridge 2.2.27 publisher-final-result precedence remains intact. DOI/source identity guards, image-quality thresholds, TIFF/currentSrc acquisition behavior, staging/publication policy and literature data are unchanged.
