# Bridge 2.2.24 — production live acceptance

Recorded 2026-09-23 18:53:35 Asia/Shanghai. This is a client capture release; it does not alter the fixed media generation, production literature corpus, inclusion scope, Chinese titles or the 08:00/18:00 literature release tasks.

## Evidence-driven change

Bridge 2.2.23 automatic reports showed an ACS-specific acquisition gap: high-resolution Figure/Scheme download variants can return TIFF bytes under `application/octet-stream`. The current Worker staging protocol accepts PNG/JPEG/GIF/WebP/SVG, not raw TIFF. In 2.2.23 the collector tried only the first four network variants, so the already loaded image belonging to the same labelled figure could remain untried. Several reports then fell back to a 520px raster candidate that could correctly fail the existing quality threshold.

This release does NOT lower the raster quality threshold and does NOT accept arbitrary octet-stream bytes. It:
- identifies TIFF magic explicitly for truthful diagnostics;
- does not upload TIFF raw;
- only after ordinary candidates fail, uses the actual `currentSrc` of the SAME isolated Figure/Scheme DOM block as a final ACS fallback;
- requires that ACS fallback URL encode the owning task DOI and still passes `assertBoundCaptureJob`, page DOI and source DOI checks;
- keeps the same quality evaluation;
- sorts the capture queue by newest date, then missing official TOC, then JACS, then stable registry order. Existing official-TOC papers remain body-only tasks.

The local progress wording is updated so a staged image is not permanently described as necessarily unpublished; actual publication state remains established by the site/ledger, not by the capture receipt.
