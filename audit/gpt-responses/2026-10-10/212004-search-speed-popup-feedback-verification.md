# Organic Synthesis Gallery 搜索速度与提示窗残留反馈核查
北京时间：2026-10-10 21:20:04（Asia/Shanghai）
对话：Gallery 搜索 LMCT 修复后，用户反映“搜索的速率太慢。而且有时候搜索的提示窗还会不消失，影响观感”。

## 当前答复同步（已向用户分段展示）

我先核查两个问题：搜索从输入到显示结果的耗时，以及关键词提示弹窗为什么有时不关闭。会检查正式代码、现有性能测试和弹窗事件逻辑，确认原因后给出具体改法；按照项目的反馈规则，这一轮先核实，不直接修改生产代码。

已经从当前正式版代码中确认两类问题。

**1. 搜索存在可避免的前端延迟。** 每次输入都会立即重建文献卡片、触发图片恢复和媒体加载调度，随后还要经过固定的 **220 毫秒防抖**，才开始全库索引检索。网络请求完成后，又会重建页面和搜索组件。部分工作重复执行，足以增加等待和界面卡顿。

**2. 搜索建议弹窗确实存在生命周期错误。** 点击某条建议时，代码可能先生成新弹窗，随后却只移除旧弹窗，并清空对新弹窗的引用。结果是新弹窗留在页面上，失去正常的关闭管理。这与你描述的“有时候提示窗不消失”直接吻合。

此外，当前按 Enter 只记录搜索历史，不会主动关闭建议弹窗；也缺少可靠的点击外部关闭机制。

我还核对了最近一次通过的正式浏览器搜索日志。单次索引请求耗时约 **0.36–0.95 秒**，但这只是 GitHub 测试环境的网络耗时，不包含页面防抖、文献卡片渲染和图片处理，也不能代表你在国内网络下的实际速度。

因此，优化不能只是让 API 更快；更重要的是减少输入期间的重复渲染，并确保旧查询不会拖慢新查询。

## 终端答复（拟同步发送）

建议把这两项作为同一批前端优化。

搜索速度方面，优先避免每次按键重建卡片及重复触发媒体、PDF 和标题增强，保持搜索输入框稳定；对连续输入做合并查询、取消过期请求、短时缓存相同检索，并记录“输入结束→索引返回→卡片可见”的分段耗时。优化防抖时会控制请求次数，避免为了提速反而增加服务器负载。

提示窗方面，改为单实例受控管理：先关闭旧建议再提交新查询；按 Enter、Esc、点击外部、选择建议、失焦或页面滚动时可靠关闭，兼容触屏与中文输入法，并补充“反复输入、连续切换、点击建议、切换页面后无残留”的浏览器回归测试。

改动仅限搜索前端和相关测试，不改变 938 篇正式目录、DOI、摘要检索逻辑、TOC、PDF 或每日 08:00 发布规则。**按照项目反馈流程，当前只完成核实，尚未提交修复或部署。是否批准将搜索提速和弹窗修复一并实施？**

## 核实证据
- main `src/main.ts`: `processCorpusSearchInput` 先 `renderCards()` 再 `scheduleArchitectureCorpusRefresh()`，默认 debounce 220ms；`renderCards` 每次重写 `#gallery.innerHTML`，接着 `restoreMedia()`、`scheduleMediaBatch(0)`、`schedulePdfVaultCardsRefresh`；D1 索引成功后 `loadIndexedViewPage` 调用 `mount()`。
- main `src/user-ui/search-controller.ts`: `renderSuggestions` 创建 `document.body` 固定浮层，候选点击 `mousedown` 处理器中先 `this.setSearch` (同步触发 `input`→`renderSuggestions` 新浮层)，随后对旧 `popover.remove()` 并 `this.popover=null`，可能将新浮层变成无引用孤儿。现有 Enter 仅 `store.addHistory`，blur 延迟150ms，缺少捕获阶段外部点击关闭、滚动关闭和 focus 守卫，选项仅绑定 mousedown。
- main `src/platform-api.ts`: 检索可优先 GET，故障时串行尝试 custom-domain/worker.dev，接着 POST 兼容；`rawRequest` 不含显式取消或超时处理。
- 浏览器实时验收工作流 #38054131192：390px GET 响应 947/380/363/388/392ms，1280px 887/370/548/366/381ms。它们是 GitHub Actions 所在环境的单次网络耗时，并非用户国内网络，也不代表端到端渲染耗时。
- `tests/search-refresh-performance.spec.ts` 只检查状态编辑与部分本地搜索的计数读取/存储写入，没有对生产 D1 输入到可见结果耗时和建议弹窗的完整退出路径设置硬门槛。
