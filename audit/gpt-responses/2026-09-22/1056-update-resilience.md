# GPT response synchronization

Beijing time: 2026-09-22 10:56 +08:00
Context: automation resilience / authoritative literature update
Related commit: e49ee794bd79413a435924bced453c2fd4f103fa

现在已经不是“失败了就算没完成”，而是改成了三层自愈链路。完成标准也改成了：**只有 review 持久化、accepted 写入、生产网页核验、TOC 队列刷新、协调状态更新全部完成，才算这一轮更新完成。**

当前北京时间调度是：
- 08:05 / 18:05：权威主更新，完整抓取 + 逐篇语义审核 + 上线；
- 08:07 / 18:07：GitHub 机器完整性审计，独立发现来源异常和漏抓；
- 08:25 / 18:25：第一兜底。如果主任务没触发、提前结束或没有形成有效提交，它会直接接管并完成整轮更新，而不是只报警；
- 08:50 / 18:50：最终终检。它会检查 review、数据、部署、线上 DOI、audit/state、TOC queue，任何一环缺失都会继续补完。

这套机制已经写入 GitHub 协调状态，commit 为 `e49ee794bd79413a435924bced453c2fd4f103fa`。因此单次漏触发、一次连接中断、主任务提前退出、部署没跟上、audit 派生写入冲突等，都不再是“本轮直接失败”的单点故障。

我仍不能对外部平台做数学意义上的 100% 保证，例如 ChatGPT 自动任务平台、GitHub、Crossref/OpenAlex、网络同时发生持续性故障时，任何系统都无法保证当时一定完成。但现在设计目标已经变成：**只要后续任一执行节点恢复可用，就自动接管并补完；不会把未完成误报为 0，也不会静默漏掉。**

所以下一次 18:05 更新，不再依赖单一一次触发。即使主任务出问题，18:25 和 18:50 还有两层自动接管。
