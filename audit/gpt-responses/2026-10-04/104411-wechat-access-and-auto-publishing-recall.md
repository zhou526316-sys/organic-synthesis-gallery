## 三、微信公众号怎样实现全自动发推文？

**有相应接口权限的账号，可以实现“自动成稿—自动排版—自动上传—自动群发—结果核对”。对你当前账号，最先要确定的是接口权限。**

### 1. 必须区分三种结果

| 自动化做到哪一步 | 实际结果 | 能否等同于正常推送给粉丝 |
|---|---|---|
| 自动生成并写入草稿箱 | 后台已经有排好的稿件 | 不能 |
| 调用发布能力，例如 `freepublish` | 形成可访问的文章 | 不能据此认定已经群发 |
| 调用群发能力 | 向符合条件的关注者发送图文消息 | 这是你要的“发推文”，还需确认最终发送结果 |

现有微信 SDK 的接口文档也明确把草稿、发布和群发分开：`freepublish` 处理发布内容，不能代替群发管理。genui{"citation":{"ref":"turn59view0"}}

**旧方案里“没有群发权限，就改成自动发布文章”的说法不够严谨。** 发布本身也有权限条件，不能保证一定可用。

你之前说过自己是个人运营，但这不足以确认现在公众号的注册主体、认证状态和接口能力。应在[微信公众平台](https://mp.weixin.qq.com/)的开发设置／接口权限页面，逐项核对：

- 素材上传；
- 草稿箱；
- 发布；
- 群发；
- 最终发送是否仍要求管理员手机确认。

腾讯官方接入文档同样要求：调用具体接口前确认对应权限，并设置调用服务器的 IP 白名单。genui{"citation":{"ref":"turn37view1"}}

本次部分微信开发文档权限页未能读取，我不会把网上流传的个人号／企业号权限表当成你账号的实测结果。如果只开放草稿能力，就能自动做到草稿箱；要实现无人值守发送，必须有可用的群发能力，并满足账号实际的发送要求。

### 2. 你的日更目标，更适合每天合并成一篇

腾讯客服目前说明：资讯类公众号每天可群发一条消息，服务号每月可群发四条，认证前后频次相同。**能在后台手动群发的额度，也不等于已经获得 API 群发权限。**genui{"citation":{"ref":"turn37view0"}}

因此，Gallery 继续按现有 08:00、18:00 更新，公众号把两批内容合成一篇日报比较合适。此前建议的 **19:10** 可以保留为候选时间，但实际触发应依赖当天文献已经正式上线；遇到网站发布延迟，要等待新数据或明确标注本期覆盖范围，避免把旧数据当作当天完整更新。

如果现有账号是服务号，推送计划就需要按月度额度设计，例如周报，不能直接套用每日群发。

## 四、适合你现有网站的具体实现

我建议采用下面这条链路，尽量复用已有工作。

### 第一步：从 Gallery 正式发布结果生成“每日清单”

公众号程序读取当天已经正式上线的文献，包括标题、期刊、DOI、已有摘要、对应图片和新域名卡片链接。

排序沿用你现有的“最新更新优先＋期刊优先级”。按网站实际收录时间确定本期新增，并用 DOI 去重，避免因为论文发表日期不同而漏掉刚收录的文章。

这样公众号可以直接继承网站的范围判断和纠错结果。

### 第二步：复用已有摘要，自动套用手机端模板

**单纯为了发公众号，不必再额外调用一次大模型 API。**

第一版可以把网站已有摘要排成固定结构：

- 本期更新概览；
- 按既定顺序排列的文献条目；
- 每篇的中文标题、期刊、DOI、核心内容和对应图片；
- 末尾“进入有机合成文献库”的阅读原文入口。

已经有摘要的使用现有摘要；只有原始摘要的，内容保持在原始摘要能支持的范围；信息缺失的条目不补写产率、选择性或机理。以后确实需要更强的专题解读，再单独增加编辑环节。

你要求的手机阅读体验也可以固化在模板里：单栏、短段落、清楚的小标题、足够留白、化学图片不裁掉结构。无需每天重新做一套版式。

### 第三步：整理图片，生成微信草稿

设计上先把正文图片和封面上传为微信可用素材，再生成草稿。每張图都和 DOI 绑定，生成后读回草稿核对标题、图片和链接，尤其防止你之前遇到的图片串篇问题。

网站介绍类推文继续使用真实网页截图；日常文献日报采用对应文献的图片和简洁封面。图片暂缺时采用明确的文字条目，不生成看似真实的替代反应图。

### 第四步：复用原来的固定 IP 服务器

你已经为微信分享搭过固定 IP 中转，仓库里也有实现。后续应先检查这台服务器的运行状态，再在同一基础设施上增加发文服务，无需一开始就另买服务器。[已有中转服务说明](https://github.com/zhou526316-sys/organic-synthesis-gallery/blob/a5de5a3462cd1c13915f0a8888677d64f799d1bf/ops/wechat-ticket-relay/README.md)

服务器负责定时取清单、排版、上传和调用微信接口。AppSecret 等凭据保存在服务端，微信 API 从已加入白名单的固定出口调用。现有中转目前负责分享签名所需票据，发文能力还需要另外实现。

### 第五步：按权限执行，并记录最终结果

这里需要三条明确分支：

- **具备群发权限：**提交图文群发，查询最终状态，记录文章和发送结果。
- **只有发布权限：**发布可访问文章，记录文章链接，不标记为“已通知粉丝”。
- **只有草稿权限：**稿件准备完成，最后通过官方后台发送。

可靠运行还需要处理你之前在网站自动发布中反复遇到的“任务跑了，但内容没真正上线”问题：

**同一账号、同一天、同一期日报只能有一个发送任务。** 数据后来补齐，可以更新尚未发送的草稿；发送成功之后，不能因为清单发生变化而自动再群发一次。遇到请求超时，先核对微信端是否已经受理，不能直接重发。状态必须区分“草稿就绪、提交发送、发送成功、失败或结果待核实”。
