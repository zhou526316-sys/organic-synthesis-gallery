## Reply body

可以实现，而且我认为这个方向很值得做。它能同时解决三个当前痛点：你的账号可以直接看原文 PDF；HTML 页面难抓 TOC/正文图时，PDF 可以作为第二证据源；摘要可以优先基于完整 PDF 文本，而不是只依赖 abstract 或不完整 HTML。

但我不建议把“PDF”简单塞进现有正文图流程里。更稳妥的方案是：**一个 Tampermonkey 安装脚本，内部拆成两个完全独立的模块——现有媒体抓取模块 + 新 PDF 捕获模块。** 这样你仍只维护一个脚本、一个更新链接，也能复用同一次出版社登录和同一个文章页面；但 PDF 下载失败、文件过大、出版社拒绝 PDF 请求，都不能把 TOC/正文图任务判失败或阻塞后续队列。PDF 模块可以随时单独关闭。

我刚核对了当前账号系统：已经有用户、session 和 Bearer token，但 session 返回的还是基本用户资料，没有真正的“角色/权限”字段。因此不用重做登录系统，只需要在现有 D1 上增加一层 entitlement，例如 `private_pdf`。第一阶段我建议只给你的账号这个权限，不急着做收费等级或给其他用户开放。

账号行为可以设计成这样：

| 账号 | 点击“原文”后的行为 |
|---|---|
| 你的 owner 账号 + 已存 PDF | 直接打开站内 PDF 阅读器 |
| 你的 owner 账号 + PDF 尚未抓到 | 跳转出版社原文页 |
| 普通注册账号 | 始终跳转出版社原文页 |
| 未登录用户 | 始终跳转出版社原文页 |

这个权限必须由 Worker 在服务器端判断，不能只靠前端隐藏按钮。PDF 也不能放进 GitHub Pages、公开 media 路径或可猜测的 R2 URL。建议单独放进私有 R2，例如 `private-pdf/<doi>/<sha256>.pdf`；账号通过 `/api/article-pdf/access?doi=...` 请求，Worker 验证 session 和 entitlement 后，返回一个几分钟有效的临时阅读 URL。这样浏览器可以正常使用 PDF 原生阅读器和 Range 请求，而普通账号永远拿不到真实私有地址。

Tampermonkey 的 PDF 抓取逻辑也应和图片分开记账。它只处理浏览器本来就能合法打开的 PDF，不绕过付费墙、DRM、验证码或出版社权限。每份 PDF 至少记录 DOI、出版社、原始文章 URL、PDF 来源 URL、SHA256、文件大小、抓取时间和来源绑定。只有响应确实是 PDF、来源与当前 DOI/出版社匹配时才入库。建议另设 PDF 写入端点和独立写权限，不直接复用图片发布链路。

PDF 对现有系统最有价值的其实是后处理。PDF 入库后，可以异步做三件事：第一，提取全文文字，写入现有私有 evidence，摘要就能优先使用完整正文；第二，从 PDF 的 Figure/Scheme/Chart caption 和页面坐标提取高分辨率正文图，作为 HTML 抓图失败时的 fallback；第三，识别 graphical abstract/TOC graphic。这里要保留你现有的严格语义：**PDF 中明确标识的 TOC/graphical abstract 才能升级为官方 TOC 来源；普通 Figure 1 或模型猜测出来的“看起来像 TOC”的图，仍只能是 fallback，不能冒充官方 TOC。**

对于“让 GPT 从 PDF 里找图”，我建议 GPT 只参与语义判断，不直接决定数据是否可信。更稳的流程是先用 PDF 文本层/页面坐标确定 Figure 1、Scheme 2 等区域，再让模型判断哪个图适合作为摘要图、是否是 graphical abstract；最后仍经过 DOI、图号、文件摘要、尺寸和来源校验。这样不会因为模型误判破坏你现在已经建立起来的媒体完整性规则。

从工程风险看，我建议分三步上线：第一步只做你的账号的私有 PDF 查看和权限控制；第二步让 Tampermonkey 自动抓“当前账号可正常访问”的 PDF 并私有入库；第三步再接 PDF 文本/图片提取，作为摘要和 TOC/正文图的 fallback。这样即使 PDF 功能有问题，现有 TOC、正文图、全文文本、08:00/18:00 发布和整个网页都不会受影响。

还有一个边界需要明确：技术上可以私有保存，但出版社 PDF 的存储和再次提供受出版社/学校订阅许可约束。因此第一阶段最好只做**你的 owner 账号私有使用**，不把 PDF 权限直接做成面向所有注册用户的会员权益，也不绕过任何访问控制。以后如果要开放给其他账号，再单独核对授权范围。

我的建议是：**做，而且先采用“一个脚本、两个隔离模块 + owner-only 私有 PDF + 服务器端 entitlement”这套架构。** 这比再做一个完全独立的 Tampermonkey 脚本更容易复用同一次文章访问，也比把 PDF 直接混进现有图片任务安全得多。
