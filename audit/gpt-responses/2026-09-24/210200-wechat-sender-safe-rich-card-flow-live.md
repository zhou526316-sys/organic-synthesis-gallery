你说得对。刚才那个方案的问题不是“富卡信息不够”，而是**发送者和接收者共用了同一个自动跳转页面**：发送者刚打开分享页就被 0.85 秒后带走，根本来不及在微信里完成图文分享；最后从 Gallery 正文页再分享，就退化成了你截图里这种“标题 + 普通 URL”的样式。

我已经把这条链重新改了，PR #222 已合并并部署，正式 GitHub Pages #306、Card sharing CI #28、Worker 同步 #86 都已通过。

现在推荐流程不再是“电脑复制链接 → 发到微信 → 再点进去抢时间分享”，而是：

**电脑 Gallery 的论文卡片 → 分享 →「微信扫码分享图文卡片」→ 微信扫码 → 页面停住不跳转 → 自动准备标题 + 期刊/DOI + TOC → 右上角「…」→ 分享给朋友。**

关键变化有两个：

1. **发送者扫码打开的是 prepare 模式**，URL 会带 `prepare=1`。这个页面不会自动跳走，会一直显示论文标题和 TOC，并在微信内自动调用 JS-SDK 配好图文卡片。页面准备完成后会提示“图文卡片已准备好”，你只需要右上角分享一次。
2. **真正发给别人的卡片不带 `prepare=1`**。接收者看到的是标题 + 期刊/DOI + TOC 的图文卡片；他点卡片后，才会快速进入 `gallery.gczhouwld.com/?doi=...`，自动定位对应论文并保持 20 秒高亮。

所以发送者和接收者现在是两条行为：
`扫码准备页（停留，供你分享）` → `微信图文卡片` → `接收者点击` → `Gallery 对应论文高亮`。

“复制富卡链接”我仍然保留，但不再把它当微信主方案。网页无法强制微信把“手工粘贴到聊天框的 URL”渲染成带图卡片；微信官方支持的稳定方式仍然是网页在微信内通过 JS-SDK 配置分享内容，然后使用微信的“分享给朋友”。我们现在把这条路径压缩到了**扫码一次 + 右上角分享一次**，不需要再进入正文页后二次分享。

你现在直接用任意一篇已经有 TOC 的论文测试即可。电脑端不要点“复制富卡链接”，直接点 **「微信扫码分享图文卡片」**。扫码后如果页面不再自动跳走，并出现“图文卡片已准备好”，就说明新流程已经生效；然后右上角发给自己，看聊天里的最终卡片截图发我，我继续做最后一轮视觉验收。
