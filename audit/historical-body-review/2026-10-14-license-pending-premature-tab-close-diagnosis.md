# 2026-10-14 historical-text v0.2.8: premature publisher tab closure / licence false-negative investigation

- Context: User reported "大部分许可待核实，基本是文献一摊出来就自动关闭了".
- State: **defect in v0.2.8 negative-readiness/auto-close flow confirmed by code**; whether individual papers have usable licences remains unverified. **Approval hold**: user has not yet explicitly approved this feedback-specific code repair. This report is read-only diagnosis, not a repair.
- Source baseline: `main/public/gallery-historical-text-pilot.user.js` @version 0.2.8, blob SHA `3f306d482a351f63bfe5b7be24d84baf13dc6f36`.
- Owner-sanctioned private D1 report aggregation: [#38532983093](https://github.com/zhou526316-sys/organic-synthesis-gallery/actions/runs/38532983093). Only aggregate counters; **no DOI, article bodies, raw events or credentials** exposed.
- Scope of that run: newest 200 metadata events (2 pages), 178 unique terminal publisher attempts; older v0.2.5 events comprise most of the history. Only 15 identifiable final attempts come from v0.2.8, so do not extrapolate this failure rate to all 1,087 formal DOI.
- v0.2.8 final outcomes in window: **10 `license_not_verified`**, **4 `page_http_error`**, **1 `publisher_script_not_confirmed`**. Thus 10/15 (66.7%) are classified as uncertain licence among this small latest sample. Global, version-mixed totals must not be confused with the v0.2.8 sample.
- v0.2.5 older outcomes in same 200-event window: 155 timeout, 6 page_http_error, 1 body_missing, 1 license_not_verified. These are separate older workflow modes, not current 0.2.8 performance.
- Code root #1 (confirmed): `batchArticlePageReady` is true once an article-like root has >=2 `h2,h3,h4,p` elements and the document is not `loading` (line ~1651); no main-science/body/licence content evidence required.
- Code root #2 (confirmed): `batchWorker` uses `maxProbeMs=3200`; when no licence matches and a "ready" root has the same **element-count-only** signature twice, `unchangedReady>=1` immediately writes terminal `license_not_verified`, without proving the article's specific rights block or delayed async metadata is finished (~line 1704–1744). DOM text can hydrate without changing element counts; MutationObserver can wake a scan before a licence is ready.
- Code root #3 (confirmed): the parent `batchStart` *always* calls `batchTab?.close?.()` in `finally` immediately after the first matching result, regardless of whether it was successful, truly blocked, or only `license_not_verified` (~line 1521–1529). Thus quick false negative causes the tab to visibly flash and close. Closing is caused by this script, not proof of publisher refusal.
- Code root #4 (confirmed): `BATCH_CAPTURE_REVISION='historic-body-evidence-v026'` even at version 0.2.8. Prior DOI-verified `license_not_verified` with that revision will not be selected by the ordinary batch: `batchRetryAllowed` returns false unless the user requests manually blocked recheck (~line 903–922). This makes a mistaken result sticky.
- Rights selector compatibility limitation (code-confirmed, affected publishers not measured): `batchLicenseEvidence` accepts a narrow set of metadata URLs, article-scoped headings and a very exact ACS copyright sentence. It may miss genuine article-specific reuse statements in differently hydrated publisher templates. **Do not classify all such misses as CC BY, and do not remove the rights gate.**
- Negative-result limitations: some pages genuinely lack CC BY/CC0 permission; login/HTTP403/429 should stay independent hard denials. No evidence that any 10 sampled DOI are actually CC BY; prove this per publisher/paper before asserting mislicensed publication.
- Proposed fix (subject to explicit user approval): make scientific body and licence readiness event-driven rather than an element-count signature; accept DOI-verified article-scoped rights metadata only; separate `licence_pending_load` from `licence_not_verified_after_review`; do not close a still-hydrating or unresolved article immediately; retain at most a small number of manual-review tabs to prevent thousands of tabs and browser memory exhaustion; keep successful/explicitly denied tabs auto-close; retain per-DOI diagnostic status and resume/redo exactly one properly versioned recheck of prior v026 false negatives; expand individual journal selector adapters only with verified article-specific evidence.
- Required tests if approved: Chromium simulated DOI-matched page with stable headings/paragraph count and genuinely late CC BY metadata must no longer auto-fail/close before the licence arrives; publisher DOM fully loaded w/o verified CC must still not be saved; 403/429 correctly logged without retries/bypass; original local IndexedDB packets/keys preserved; no media/PDF/SI/TOC/public-FTS write; bounded review tabs; revised old-v026 failures regain one safe attempt without redoing entire history.
- **No new userscript version, PR, repair branch, deployment or production data mutation for this feedback** before approval; only this diagnostic report and owner-only read trigger have been written.
